# Evaluating Generated Storylines

This runbook covers checking whether the model behind `expand_frontier` writes storylines that read as one continuous, self-consistent story. Each root-to-leaf path is judged on its own; sibling branches are expected to diverge. `scripts/eval_storylines.py` runs the whole check unattended with one command, so there is no browser and there are no hand-built API calls.

```
make eval                      # 3 premises under the default pacing plan
make eval ITER=1 PLAN=plan.json JUDGE=1                      # another plan (a PacingPlan as JSON)
make eval POLICY='{"refine":{"rounds":2}}'                    # R1's refine loop on
make eval POLICY='{"refine":{"rounds":2}}' CONCURRENCY=10     # …fanned out against a pooled backend
uv run --project backend python scripts/eval_storylines.py judge eval-out/<stamp>   # re-grade later
```

**What it does.** `run` starts a private backend on port 8766 with `CYOA_LLM=openai`. Its `CYOA_DB` and `CYOA_AGENT_DB` point into the output folder, so the dev database from the [dev loop](dev-loop.md) is never touched and each run tests the current code. For each premise in `scripts/eval-premises.json` (a title, a description used as the story description, and an opening passage), the harness creates the story and starts `expand_frontier` from the opening passage with the `skip_review_interrupt` policy described in [agentic authoring](../concepts/agentic-authoring.md). It then polls the run until it ends, cancelling it after `max_seconds` + 120 s. Finally it reads `/graph` and `/problems` and stops the backend.

**What it writes** to `eval-out/<stamp>/` (gitignored):
- `index.md`: one row per story with run status, passages created, storyline count, endings and unfinished-storyline counts, path length, stub bodies and choices (blank or ending in `...`/`…` — the model's placeholder output), retries, seconds and run errors.
- `<n>-<slug>.md`: every storyline as continuous prose, with the choice taken between passages.
- `<n>-<slug>.json`: the same paths as data, which is what `judge` reads.
- `backend.log`: output from the private backend.

**Judging.** With `--judge`, each path is sent to the model at `CYOA_OPENAI_URL` with a rubric: contradictions, passages that ignore their choice, unintroduced references, and shifts of person or tense. The model answers `{consistent, readability, issues}`, and the verdicts are appended to the story report. It is the same model grading its own output, so treat a pass as weak evidence. A typed scorer would remove the parsing and self-grading problems; see [Story Quality Scoring](../concepts/story-quality-scoring.md). On the first run (2026-09-28) it passed a slip a human reader catches at once, so read the reports yourself before trusting it.

**Cost.** Against Qwen 3.8 27B with the Bonsai-2 ternary quantization on llama-server, each model call takes 10–20 s, and one passage costs one call plus a share of its parent's choices call. A 20-passage story took about 10–20 minutes. Judging takes roughly another 30–100 s per storyline.

**History.** The first run (2026-09-28, `eval-out/20260928-143623`) found prose that read well but had two failure modes. First, about one passage in eight was unusable: a literal `...` body or choice, or an empty tool call. Second, facts drifted when they had been set two or more passages up, because `grow` then showed the model only the parent passage. Both were fixed the same day. `grow` now retries through `_ask_until`, and every agent prompt carries the whole path from the start (the spine, see the [backend](../systems/backend.md)). The second run (`eval-out/20260928-152815`, same budget) measured the effect:
- **Junk output gone.** No placeholder passages, `...` choices or lost passages, against 7, 1 and 2 before. Every story reached its full 20 passages.
- **Facts carry to depth 3.** Fuel and oxygen readings only count down, clues and warnings set two passages up are paid off, and no storyline contradicted its premise.
- **What still slips.** Physical sequencing within a passage ("the clamps bite" after you have already left the ship; knocking before reaching the door; "let gravity do the rest" in free space). Bodies that list the reader's options ("You can strip…, ask…, or follow…"). Passage titles reused across branches (three different passages titled "The Willow at the Mill Race").

These are the first candidates for the continuity and craft auditors in [refinement loops](../concepts/refinement-loops.md). Runs since then also count retries by reason, which is the baseline for the audit-and-revise phase scoped in [refinement loops](../concepts/refinement-loops.md). The fixed context problem is only the reading half of what [choice anchoring](../concepts/choice-anchoring.md) proposes; choices still declare no world-facts.

The first run found and fixed [unattended runs stopping after one level](../incidents/2026-09-28-skip-review-stopped-after-one-level.md).

[Storyline generation quality](../syntheses/storyline-generation-quality.md) synthesizes all three runs together and closes with concrete proposals for what to fix next; this section keeps the run-by-run narrative.

The same day, the budget shape changed from a flat `max_passages` cap to `depth` (levels grown below the root) plus `branching` (choices kept per passage), with `max_passages` demoted to an optional extra ceiling. That ceiling was removed on 2026-09-29 when [act pacing](../concepts/act-pacing.md) landed. Since then the harness takes `--plan` (Make's `PLAN=`) in place of `--depth`, `--branching` and `--max-passages`. Without it, each story runs the backend's default plan, which the harness reads from the first story's `/pacing` and logs, and `--max-seconds` overrides the plan's time guard. Runs 1–4 below predate plans, so their depth/branching budgets aren't reproducible with today's flags: an equivalent plan is one act per level with that branching, which is not the same pacing. The last level always writes endings (`is_ending=1`, rendered as "— THE END —"), and the writer can end a storyline early via `ends_story`; both are described in the [backend](../systems/backend.md). The `frontier_choices` and `frontier_passage` prompts were given `{branching}`/`{remaining}` placeholders so the model is told directly how many passages are left and is steered toward resolution as the budget shrinks — the mechanism the user asked for so depth and branching could "trigger changes to the authorship prompt(s) to encourage closure." A third run (`eval-out/20260928-162631`, depth 3, branching 3, the new default) validated it: every storyline in all three stories now ends (`endings == unfinished == storylines`: 7/7, 5/5, 6/6), the endings read as genuine resolutions rather than cliffhangers, and zero stub bodies or choices survived (7, 1, and 8 retries respectively were all caught and rewritten). Trees came out smaller than the depth/branching ceiling allows — 10, 7, and 8 passages against a 39-passage maximum — because the model mostly took the prompt's "fewer when the moment holds fewer real options" instruction literally and offered 2 choices instead of 3; this is the closure behavior working, but worth watching if `branching` is tuned up and trees stay this thin. The duplicate-passage-title issue from run 2 did not reappear in run 3's three stories, though the sample is small.

A fourth run (`eval-out/20260928-191304`, same depth 3 / branching 3 budget) swapped the model server: the owner restarted `llama-server` on `gemma-4-12B-it-uncensored-Q4_K_M.gguf` (Gemma-4 12B, Q4_K_M) in place of Qwen 3.8 27B with the Bonsai-2 ternary quantization. Two things moved together: speed (124/130/86 s versus 1280/1206/653 s — the 12B model is roughly 8–10× faster per run on this machine) and tree size (21/24/17 passages versus 10/7/8, against the same 39-passage ceiling). Endings still matched storylines exactly (14/14, 16/16, 10/10) and stub bodies/choices stayed at zero, so the retry mechanism and the depth/branching closure logic hold across models. Retries dropped to almost none (1, 0, 0, versus 7, 1, 8), meaning this smaller model produced well-formed structured output on nearly the first try. One new, narrow failure mode showed up that hadn't in the three Qwen/Bonsai runs: a literal `\n\n` (backslash-n, not a real newline) leaked into one passage body's prose (`1-the-lighthouse-keeper-s-debt.md`, storyline 10) — a rendering artifact `_blank`/`_placeholder_body` don't catch because the text isn't blank or a placeholder, just malformed. [Storyline generation quality](../syntheses/storyline-generation-quality.md) compares all four runs and updates its proposals against this new data.
