# Running the Dev Loop

Two processes, driven from the root `Makefile` (`make help` lists every target). Run `make install` once to `uv sync` the [backend](../systems/backend.md) and `npm install` the [frontend](../systems/frontend.md).

```bash
make backend    # FastAPI with reload on 127.0.0.1:8765
make frontend   # Vite on 5173, proxying /api to the backend
```

Open http://localhost:5173. The backend creates `backend/cyoa.db` on first start; delete it to reset — there are no migrations while the [story model](../concepts/story-model.md) is unstable. If 8765 collides, set `CYOA_PORT` for the backend and `CYOA_API` (a full URL) for the Vite proxy.

For a single process on one port — no Vite, no proxy — use `make serve` instead: it runs `npm run build` then starts the backend (reload off) with the built frontend mounted at `/`, as [the backend page](../systems/backend.md) describes. Open http://localhost:8765. Rerun `make serve` after a frontend change; there's no watch mode in this path.

LLM routes need a model server. `make backend` sets `CYOA_LLM=openai`, which talks to an OpenAI-compatible server at `CYOA_OPENAI_URL` (default `http://localhost:8080/v1` — the owner's `llama-server` with Qwen 3.8 27B, Bonsai-2 ternary quantization); `CYOA_LLM=ollama make backend` uses a local Ollama at `OLLAMA_URL` (default `http://localhost:11434`) instead. Both cannot fit on the 12 GB GPU at once. `GET /api/llm/models` is the quickest check, and returns 503 with the URL when the server is down. `OLLAMA_MODEL` picks the default model for the assist verbs; the model picker in the top bar overrides it per browser. Verbs answer in roughly 5–20 s on a 27B model with reasoning off — if one takes minutes, the model is thinking, which `llm.chat_model()` disables and a new model may not honour. If every assist fails with `cudaMalloc failed: out of memory`, check `nvidia-smi` for another process holding the GPU (a stray `llama-server` did on 2026-09-20) before suspecting the code; `CYOA_AGENT_CONCURRENCY` (default 1) caps how many model calls the whole backend keeps in flight, per [the fan-out OOM incident](../incidents/20260920-fanout-oom.md). That default of 1 is for a single local model instance, where two concurrent contexts don't fit; against a load-balancing proxy fronting a pool of instances — the owner verified one at `http://localhost:4000/v1` on 2026-09-28, an OpenAI-compatible endpoint that owns request queuing across its own pool — raise `CYOA_AGENT_CONCURRENCY` to match the pool size (e.g. `CYOA_AGENT_CONCURRENCY=10 CYOA_OPENAI_URL=http://localhost:4000/v1 make backend`) so generation actually fans out concurrently instead of only being permitted to; `agents.py`'s `_fan` helper and `_GATE` (both described in [the backend](../systems/backend.md)) are what turned "permitted" into "actual" that day. Runs keep their LangGraph checkpoints in `CYOA_AGENT_DB` (default `./cyoa-agent.db`); deleting `cyoa.db` alone leaves orphaned checkpoints behind, which is harmless, and deleting both resets everything. A run that was mid-node when the backend stopped is marked failed on the next start; a paused one can still be resumed. To exercise runs without a GPU, start a scratch backend with `llm.chat_model` monkeypatched to a fake that sleeps a second per call — that is how the phase-5 UI was verified. When smoke-testing a code change against a running scratch backend, start it with `--reload` or restart it — a stale process quietly runs the old code.

`make test` runs `pytest` in the backend and `tsc -b` + `vite build` in the frontend; `make lint-wiki` runs this wiki's structural lint.
